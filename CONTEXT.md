# Project Context & Developer Handover: Complex Function Plotter (Standalone)

This document serves as an exhaustive technical handbook and architectural context registry for any AI developer or engineer inheriting this codebase. It provides 100% of the required context to understand, debug, maintain, and extend this application without prior orientation.

## 1. Project Overview & Architectural Scope

The **Complex Function Plotter** is an interactive, web-based, real-time visualization widget for complex-analytic functions ($f: \mathbb{C} \to \mathbb{C}$) using **domain coloring**. 

The codebase was migrated and completely overhauled from a legacy 2018 Create React App (React 16 ejetado, Webpack, JS) into a **modern, high-performance standalone React 19 + TypeScript + Vite + Tailwind CSS v4 widget**.

### Standalone Portfolio Integration
This repository is compiled into static production assets served via **GitHub Pages** (deployed directly using GitHub Actions). It is designed to run in complete isolation and is optimized to be embedded in external applications, blogs, or portfolios (such as the main portfolio site at `https://racoci.github.io/`) using a sandboxed `<iframe>`:

```html
<iframe src="https://racoci.github.io/complex-function-plotter/?lang=pt" />
```

## 2. Modern Tech Stack & Configurations

*   **Runtime & Framework:** React 19.2.4 (utilizing Hooks, Refs, and modern React 19 StrictMode rendering).
*   **Language:** TypeScript (configured for strict type safety and ES2022 compatibility).
*   **Build Tool:** Vite 6.1.0 (enables ultra-fast HMR and minified, single-chunk bundler deployment).

*   **Parsing Parser:** Nearley (`nearley` ^2.20.1) — a fast, robust Earley parsing grammar engine used to parse algebraic mathematical expressions.

## 4. The Core Compilation & Rendering Lifecycle

When a user types an expression or interacts with the canvas, data flows through the following compiler and GPU pipeline:

```
[User Input in MathLive Field]
              |
              v (LaTex string, e.g., "z^2 + c")
[mathlive-converter] ---> Translates math-field string to algebraic text: "z^2 + c"
              |
              v (Algebraic string)
[Nearley Parser (grammar.ts)] ---> Compiles string into a Raw AST (Abstract Syntax Tree)
              |
              v (Raw AST)
[compiler.ts] ---> Performs constant folding and algebraic simplification (Optimized AST)
              |
              +----------------------------+----------------------------+
              | (Optimized AST)                                         | (Optimized AST)
              v                                                         v
[to-glsl.ts]                                                [to-js.js]
              | (GLSL String)                                           | (JS Executable Function)
              v                                                         v
[shaders.ts] ---> Compiles WebGL Shader Program on GPU     [custom-functions.ts] ---> Computes exact
              |                                                         |                      numerical values
              |                                                         |                      for coordinate HUD
              v                                                         v
[scene.ts (drawScene)] ============================================> [CoordinateOverlay HUD]
(Renders WebGL domain coloring canvas)                                (Displays "f(z) = ..." near cursor)
```

### The WebGL Shader Representation System (Cartesian vs. Log-Cartesian)
To bypass GPU single-precision floating-point overflow and underflow limits ($1e^{-38}$ to $1e^{38}$), the mathematical translators support dual coordinate systems:
1.  **Standard Cartesian:** Ideal for low-magnitude values.
2.  **Log-Cartesian (`vec3`):** Represents complex $w$ as a normalized direction vector $\vec{u} = (x/\|w\|, y/\|w\|)$ on the plane and its natural log magnitude $\ln(\|w\|)$ in the third component. This expands the representable exponent range to over $\pm 10^{15}$, preventing shader blowouts near poles (like the Gamma function) or singularities.

### Supersampling & Anti-Moiré Shader Guardrails
The Fragment shader automatically prevents alias distortion:
*   **4-Rook Supersampling:** Renders and averages four diagonal pixel offsets ($+A, -A, +B, -B$) in the fragment shader to produce smooth gridlines.
*   **Anti-Moiré Derivative Filter:** Estimates the local spatial derivative (stretch factor). If the frequency of gridlines or checkerboards exceeds the display resolution, the shader automatically fades them out into a neutral gray, preventing artificial Moiré patterns.

## 5. Key Interactive Features & State Management

### Draggable Auxiliary Parameters
*   The system extracts all free variables from the parsed expression (excluding $z$ and constants like $i$, $e$, $\pi$).
*   These are rendered as tactile neon drag handles on the canvas. Dragging a variable on screen maps its pixel position back to a complex number $[re, im]$ relative to the current logarithmic zoom scale (`log_scale`), center offset, and canvas width/height.
*   The coordinate conversion is mathematically managed via relative canvas scaling in `ComplexPlotter.tsx`:
    *   $\text{Scale} = e^{\text{log\_scale}}$
    *   $\text{re} = \text{center\_x} + \frac{x - \text{width}/2}{\text{Scale}}$
    *   $\text{im} = \text{center\_y} + \frac{\text{height}/2 - y}{\text{Scale}}$

### IFrame Multilíngue (Language Router)
`App.tsx` reads the URL parameters at launch:
*   If `window.location.search` contains `?lang=pt`, the state `lang` is set to `'pt'`, causing `ComplexPlotter` to translate all titles, tooltips, settings drawers, and axes descriptions into Portuguese (Brazil).
*   Otherwise, it defaults to English (`'en'`).

## 6. How to Debug & Maintain the Project

### Standard Developer Workflow
1.  **Run Dev Server:** `npm run dev`. This launches the Vite server locally (usually at `http://localhost:5173/`).
2.  **Add a New Complex Function:**
    *   Add the parser syntax mapping in `src/components/complex-plotter/gl-code/grammar.ne`.
    *   Compile the Nearley grammar: In a terminal, run `npx nearleyc grammar.ne -o grammar.ts` inside the `gl-code` directory.
    *   Write the WebGL GLSL definition in `src/components/complex-plotter/gl-code/complex-functions.ts`.
    *   Add the corresponding CPU-side Javascript math evaluation in `src/components/complex-plotter/gl-code/translators/custom-functions.ts` to support coordinate overlay HUD evaluations.
3.  **Run Build Verification:** `npm run build`. This runs TypeScript checks (`tsc`) first. If there are typing or unused variable compilation warnings, the build will safely bail (exit code 2).

### Common Debugging Traps
*   **MathLive Integration:** MathLive custom elements must operate as **uncontrolled inputs** in React. To update the value without destroying the user's cursor position or causing circular rerender loops, bind to the math-field element via `ref` and update `ref.current.value` selectively (only when it diverges from the active state). Ensure `'math-virtual-keyboard-policy': 'manual'` is passed as a property to prevent virtual keyboard flicker on desktop.
*   **Shader Compilation Failures:** If an unsupported function or invalid variable name is passed, the WebGL shader compiler will bail. The compilation errors are piped directly to the **Browser Developer Console** via `console.error` containing the compiled GLSL string with line numbers. Check the console instantly to identify syntax errors.
*   **Unused Imports & Types:** Vite production compiler is configured with strict static checks. Ensure zero unused local variables or imports remain active before triggering a push to prevent build bails.

## 7. CI/CD Deployment Pipeline

An automated GitHub Actions workflow is located in `.github/workflows/deploy.yml`. 
On every push to the `master` branch:

2.  Installs verified npm dependencies cleanly (`npm ci`).

## 8. Production Deployment & Troubleshooting (MIME-Type & CDN Caching Guardrails)

### MIME-Type Error: "Expected a JavaScript-or-Wasm module script but the server responded with a MIME type of 'application/octet-stream'"
*   **Root Cause:** This error occurs when the browser requests `./src/main.tsx` instead of the Vite compiled JS bundle (`./assets/index-[hash].js`). Standard web servers (like GitHub Pages) do not recognize the `.tsx` extension and default to serving it as `application/octet-stream`. Browsers block this file per HTML5 strict MIME-type module spec.
*   **Resolution:** 
    1. Always ensure that `index.html` references the script using a relative path: `<script type="module" src="./src/main.tsx"></script>` (with the leading dot), allowing Vite to safely intercept, bundle, and rewrite the reference to `./assets/index-[hash].js`.
    2. Ensure the GitHub Pages settings have their deployment Source set to **"GitHub Actions"** instead of **"Deploy from a branch"** (which serves raw master files).

### GitHub Actions Direct Deploy vs. Branch-Based Overwrites
*   The pipeline uses **Direct GitHub Actions Pages Deployment** (the modern standard, which builds and deploys zip artifacts securely without requiring any git-branch pollution).
*   **Important Setting:** In the GitHub Repository **Settings -> Pages -> Build and deployment -> Source**, you MUST select **"GitHub Actions"**. If this is set to "Deploy from a branch", GitHub Pages will ignore our direct deployments and automatically trigger a hidden `"pages build and deployment"` job that serves the raw `master` branch files, leading to immediate MIME-type crashes.

## 9. Recent Architecture Enhancements (Subscripts, Loop Unrolling, Safety Guards, & Fluid Editor)

### A. Subscript Variable Support
The Nearley parser grammar (`grammar.ne`) and translators are configured to parse and evaluate complex variables with subscripts (e.g. `c_1`, `c_{12}`, `c_{k-1}`). The compilers accurately propagate these variable tokens to the WebGL rendering pipeline and LaTeX output layers.

### B. Closed-Loop Recursive Unrolling ($f_k$)
To render recursive indexed functions like $f_k(z) = f_{k-1}(z - c_k)$ with case $f_0(z) = z$ without GPU-side stack frames (forbidden in WebGL fragment shaders), the translation pipeline unrolls recursion into a closed, flat linear form at compilation time. 

### C. Prompt Selection Overlay
Before visualizing indexed functions, the app overlays a backdrop-blur modal forcing the user to select the value of $k$ (e.g., $f_{k=37}(z)$), allowing the compiler to perform deterministic AST unrolling.

### D. Multi-Line Fluid Text Formula Editor
The active custom function definitions are managed via a single, responsive, multi-line `<textarea>` inside the left accordion sidebar. It parses and validates formulas line-by-line as the user types, reporting errors in a red list directly beneath the editor with custom transparent emerald scrollbars.

### E. Security Guardrails
Strict safety limits prevent CPU/GPU freezes:
1. **AST Depth Check:** Rejects expressions exceeding $100$ node depth.
2. **Loop Iteration Limits:** Limit sum/product loops to a maximum of $1000$ iterations.
3. **JS/CPU-Side Pre-Evaluation Gate:** Evaluates newly defined formulas at a test point on the CPU with a strict execution timeout before triggering WebGL shader compilation.
